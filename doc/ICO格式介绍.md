# ICO 图标格式详解

## 1. 什么是 ICO？

**ICO**（Icon）是 Microsoft Windows 专用的图标文件格式，文件扩展名为 `.ico`。它是 Windows 应用程序、文件夹、快捷方式等视觉标识的标准载体。

与普通的 PNG/JPG 图片不同，ICO 的核心理念是**"一个文件，多份图像"**——同一个 ICO 文件内部可以嵌入多张不同尺寸、不同颜色深度的图像，Windows 会根据实际使用场景自动挑选最合适的那一张。

---

## 2. ICO 文件内部结构

ICO 文件由三部分组成：

```
┌─────────────────────────────────────┐
│            ICONDIR                  │  ← 文件头（6 字节）
│  - 保留字段 (2 字节，固定为 0)       │
│  - 图像类型 (2 字节，图标=1)         │
│  - 图像数量 (2 字节，如 6)           │
├─────────────────────────────────────┤
│         ICONDIRENTRY[0]             │  ← 第 1 张图像的目录信息（16 字节）
│         ICONDIRENTRY[1]             │  ← 第 2 张图像的目录信息
│              ...                    │
│         ICONDIRENTRY[N-1]           │  ← 第 N 张图像的目录信息
├─────────────────────────────────────┤
│          图像数据 1                  │  ← 第 1 张图像的像素数据
│          图像数据 2                  │  ← 第 2 张图像的像素数据
│              ...                    │
│          图像数据 N                  │  ← 第 N 张图像的像素数据
└─────────────────────────────────────┘
```

### 2.1 ICONDIR（文件头）

| 字段 | 大小 | 说明 |
|------|------|------|
| `idReserved` | 2 字节 | 保留，始终为 `0` |
| `idType` | 2 字节 | 资源类型：`1` = 图标（ICO），`2` = 光标（CUR） |
| `idCount` | 2 字节 | 文件中包含的图像数量 |

### 2.2 ICONDIRENTRY（图像目录项）

每个图像对应一个 16 字节的目录项：

| 字段 | 大小 | 说明 |
|------|------|------|
| `bWidth` | 1 字节 | 图像宽度（像素），`0` 表示 256 |
| `bHeight` | 1 字节 | 图像高度（像素），`0` 表示 256 |
| `bColorCount` | 1 字节 | 颜色数，`0` 表示 ≥256 色 |
| `bReserved` | 1 字节 | 保留，始终为 `0` |
| `wPlanes` | 2 字节 | 色彩平面数，通常为 `1` |
| `wBitCount` | 2 字节 | 每像素位数（位深），如 `32` |
| `dwBytesInRes` | 4 字节 | 图像数据大小（字节） |
| `dwImageOffset` | 4 字节 | 图像数据在文件中的偏移量 |

> **注意**：当尺寸为 256×256 时，`bWidth` 和 `bHeight` 存储为 `0`（因为 1 字节最大只能存 255）。

## 3. 图像数据格式

ICO 中的每张图像可以采用两种格式存储：

### 3.1 BMP 格式（传统）
- Windows XP 及更早版本的唯一选择
- **无压缩**，文件体积大
- 包含 XOR 掩码（图像本身）和 AND 掩码（透明度）
- 一张 256×256 的 32 位 BMP 图像约占用 **256 KB**

### 3.2 PNG 格式（现代，推荐）
- **Windows Vista 起支持**
- **无损压缩**，体积显著缩小
- 原生支持 Alpha 通道（透明度）
- 同样 256×256 的 PNG 图像通常只需 **10~50 KB**

> 本工具（SVG Converter Tool）生成的 ICO **全部使用 PNG 嵌入格式**，因此 6 个尺寸合计通常只有 10~20 KB。

## 4. 为什么需要多尺寸？

Windows 会在不同场景下使用 ICO 中不同尺寸的图像：

| 尺寸 | 典型使用场景 |
|------|-------------|
| **16×16** | 任务栏图标、标题栏图标、列表视图、树形控件 |
| **24×24** | 工具栏图标（旧版 Windows） |
| **32×32** | 桌面快捷方式（经典 DPI）、详细信息视图 |
| **48×48** | 桌面快捷方式（标准）、中等图标视图 |
| **64×64** | 大图标视图、高 DPI 屏幕 |
| **128×128** | 超大图标视图、Retina/4K 屏幕 |
| **256×256** | 资源管理器缩略图（Extra Large Icons）、最高 DPI |

### 如果某个尺寸缺失会怎样？

Windows 会**强制缩放**最接近的尺寸来填补空缺：
- 把 48×48 缩放到 16×16 → **边缘模糊、细节丢失**
- 把 16×16 放大到 256×256 → **严重马赛克**

因此，生成包含完整尺寸阶梯的 ICO 是确保图标在所有场景下都清晰锐利的最佳实践。

---

## 5. 颜色深度（位深）

除了尺寸，ICO 还支持不同的颜色深度：

| 位深 | 颜色数 | 透明度 | 适用场景 |
|------|--------|--------|----------|
| 1 bpp | 2 色 | 无 | 早期单色图标 |
| 4 bpp | 16 色 | 无 | 早期低彩色图标 |
| 8 bpp | 256 色 | 无 | 老式 8-bit 图标 |
| 24 bpp | 1677 万色 | 无 | 不透明图标 |
| **32 bpp** | 1677 万色 | **8-bit Alpha** | **现代标准，推荐** |

> 本工具生成的 ICO 统一使用 **32 bpp（24 位颜色 + 8 位 Alpha 透明度）**，这是当前 Windows 开发的事实标准。

## 6. ICO vs 其他格式对比

| 特性 | ICO | PNG | SVG |
|------|-----|-----|-----|
| 多尺寸单文件 | ✅ 原生支持 | ❌ 单张图像 | ❌ 矢量描述 |
| Windows 原生图标 | ✅ 直接支持 | ❌ 需转换 | ❌ 需转换 |
| 透明度 | ✅ 32 bpp Alpha | ✅ Alpha 通道 | ✅ 原生透明 |
| 文件体积 | 中（PNG 嵌入后小） | 小 | 极小 |
| 无损缩放 | ❌ 位图，会失真 | ❌ 位图，会失真 | ✅ 矢量，任意缩放 |
| 编辑难度 | 需专用工具 | 简单 | 需矢量编辑器 |

**总结**：
- **SVG** 是源文件，适合设计和编辑，但不能直接用作 Windows 图标
- **PNG** 是通用图像格式，适合网页和素材交换
- **ICO** 是 Windows 图标的最终交付格式，专门解决"一份文件、多尺寸适配"的需求

## 7. 本工具的 ICO 生成原理

SVG Converter Tool 的 ICO 生成流程：

```
┌──────────┐     ┌──────────────────┐     ┌─────────────┐
│  SVG 源   │ ──▶ │  SharpVectors    │ ──▶ │ 多尺寸 PNG  │
│  文件     │     │  渲染为位图      │     │ (16~256)    │
└──────────┘     └──────────────────┘     └─────────────┘
                                                  │
                                                  ▼
┌──────────┐     ┌──────────────────┐     ┌─────────────┐
│  ICO 文件 │ ◀── │  写入 ICO 头部   │ ◀── │ PNG 字节流  │
│  .ico    │     │  + 目录项        │     │ 按尺寸打包  │
└──────────┘     └──────────────────┘     └─────────────┘
```

具体步骤：

1. **读取 SVG** — 使用 `FileSvgReader` 解析 SVG 矢量数据
2. **逐尺寸渲染** — 对每个目标尺寸（16/32/48/64/128/256）创建 `RenderTargetBitmap`
3. **编码为 PNG** — 使用 `PngBitmapEncoder` 将位图压缩为 PNG 字节流
4. **组装 ICO** — 写入 `ICONDIR` 头 + 6 个 `ICONDIRENTRY` + 6 段 PNG 数据

### 生成的 ICO 规格

| 属性 | 值 |
|------|-----|
| 图像数量 | 6 张 |
| 尺寸 | 16, 32, 48, 64, 128, 256 |
| 位深 | 32 bpp（RGBA） |
| 图像格式 | PNG（压缩嵌入） |
| 典型体积 | 10 ~ 20 KB |

## 8. 常见问题

### Q1: 为什么 ICO 文件比单个 PNG 大？
因为 ICO 内部包含了 **6 张不同尺寸的 PNG**。虽然每张都经过压缩，但 6 张加起来自然比单张大。

### Q2: Windows 10/11 还支持旧版 BMP 格式的 ICO 吗？
支持，但**强烈建议使用 PNG 嵌入**。BMP 格式的 ICO 在 256×256 尺寸下会膨胀到 256 KB 以上，而 PNG 格式通常只需 20 KB。

### Q3: 为什么 256×256 的尺寸在 ICO 目录中显示为 0？
ICO 的 `ICONDIRENTRY` 用 1 字节存储宽高，最大值是 255。256 被编码为 `0`，这是格式规范定义的行为，Windows 解析时会正确识别为 256。

### Q4: 可以给 ICO 添加超过 256×256 的尺寸吗？
技术上可以（如 512×512），但 Windows 标准规范最大为 256×256。更大的尺寸不会被系统利用，反而增加文件体积。

### Q5: 如何验证 ICO 内部包含哪些尺寸？
- **Windows 资源管理器**：右键 `.ico` → 属性 → 自定义 → 图标预览
- **Visual Studio**：打开 `.ico` 文件，会显示所有尺寸图层
- **在线工具**：如 `icoconvert.com`、`convertio.co`
